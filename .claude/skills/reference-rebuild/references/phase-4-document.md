# Phase 4: document and report

## The document set

- `README.md`: what the template is and which references it follows; how to launch a client in numbered steps (copy, install, pick a preset, fill the config, add images, colours and fonts, proof and tracking and legal, run locally, check, deploy, domain, wire the form); what is in the box; the sections and presets; tracking; how to add a section type; licence notes for bundled fonts and a statement that no reference images, logos or wording are included.
- `docs/sections.md`: the catalogue. A table mapping what a client has (reviews or not, matched photo pairs, videos, a named owner, suppliers, a guarantee, recurring questions) to the sections to use; then every type with job, assets, count range, layouts and what to swap in when the asset is missing; how to run the content checker on a preset.
- `docs/content-spec.md`: generated by `scripts/build-content-spec.mjs` from the slot spec and the image specs, grouped by section: every text slot with purpose, target, accepted range and a link to its exemplar pattern; every image slot with export size, ratio, shot and crop; the supported count ranges; a shot-list summary.
- `docs/decisions.md`: every judgement call, one line of reasoning each, grouped by phase, newest at the bottom.
- `docs/verification.md`: Lighthouse tables per page and preset, first-screen numbers, section heights built versus reference, the check count and result, interactions carried over and deliberately not reproduced, what could not be verified.
- `CLAUDE.md`: what a later session does to build a client page from this template: the inputs required, the never-invent rules, where to write copy from (exemplar and content spec), how to place images, what to set (proof, pixel, legal, lead destination), the check sequence in order, the pull request format, and what not to edit (`src/`, `scripts/`, the teardown, the exemplar, the reference captures).
- Optional but worth it when the user runs this for clients: `docs/launch-playbook.md` (one-time setup, per-client steps, definition of done, missing-asset table) and `docs/intake-brief.md` (call questions mapped to slots, the asset list for the client).

## The final report

End the session with a report that stands on its own for someone who did not watch the work:

1. What the reference is and what it sells, in two sentences, and the persuasion sequence as one chain.
2. The stack and why.
3. The section types and presets shipped (and in `EXTEND` mode, which are new types and which are layout variants).
4. Lighthouse scores for every page and preset, in a table.
5. First-screen fit numbers at 390x664.
6. Every deviation from the reference and the reason.
7. Every accessibility fix made to the reference's design.
8. What could not be verified and why.
9. Where each deliverable lives (files and folders), and the commit and branch.

Keep numbers in tables, one idea per sentence, no em dashes.
